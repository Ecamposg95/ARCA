# ARCA MVP M0+M1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A deployed ARCA on Railway where a user registers, gets a seeded company, records income/expenses against financial accounts, and every operation posts balanced double-entry journal entries feeding a live dashboard and basic reports.

**Architecture:** Single FastAPI service serving a built React SPA; PostgreSQL; Alembic migrations on deploy; domain modules under `app/domains/<x>/` (router/service/schemas) with shared SQLAlchemy models in `app/models/`; the accounting engine as the single posting choke point in `app/services/accounting/`.

**Tech Stack:** Python 3.11, FastAPI 0.127, SQLAlchemy 2.0, Pydantic v2, Alembic, python-jose, passlib+bcrypt, pytest+httpx / React 18, TypeScript, Vite 5, React Router v6, TanStack Query v5, Zustand, Axios, Tailwind, Recharts / Railway + Nixpacks.

**Spec:** `docs/TASK_PACK.md` (product) + `docs/superpowers/specs/2026-08-24-arca-mvp-design.md` (decisions).

## Global Constraints

- Python 3.11 (`runtime.txt`), Node 20 in Nixpacks.
- Money: `Numeric(14,2)` / `Decimal`; schema boundary `amount: Decimal = Field(gt=0)`. Never float.
- Every tenant table: `String(36)` UUID pk, `organization_id String(36) NOT NULL` FK indexed, `created_at/updated_at` tz-aware.
- Every business query filters `organization_id` from validated context (`get_current_org_id`), never from payload.
- Journal entries: `sum(debit) == sum(credit)` enforced in `post_journal_entry()`; all posting goes through it.
- API: `/api/<domain>`, plural nouns, no trailing slash; pagination `{items, total, limit, offset}`; errors `{"detail": "<human Spanish message>"}`; responses via `Schema.model_validate()`.
- Env: `DATABASE_URL`, `SECRET_KEY` (≥32 chars, fail-fast in prod), `CORS_ORIGINS`, `ENV`, `PORT`, `DOCS_ENABLED`, `ACCESS_TOKEN_EXPIRE_MINUTES`.
- Migrations: Alembic only; files `YYYYMMDD_NN_slug.py`, `revision="YYYYMMDD_NN"`; single head; model modules imported in `alembic/env.py`.
- UI copy Spanish; code English; commits Spanish Conventional Commits.
- No hard delete of posted financial records; `status=CANCELLED` pattern.

**Produces:**
- `Account(code, name, type ∈ ASSET|LIABILITY|EQUITY|REVENUE|EXPENSE, parent_id, active, system bool)` unique (org, code).

Raises `UnbalancedEntryError` / `AccountingError` (ValueError subclasses → 400 with Spanish detail).
- `account_balance(db, org_id, account_code_prefix=None, ...)` and `trial_balance(db, org_id)` helpers (debit-normal for ASSET/EXPENSE).

### Task 6: Financial transactions + income + expenses (the M1 core)

**Files:** `app/models/{transaction,income,expense,contact}.py` (`Customer`, `Vendor` in contact.py), `app/core/events.py`, `app/services/transactions.py`, `app/domains/{transactions,income,expenses,customers,vendors}/{router,service,schemas}.py`, finish `rules.py`, `tests/{test_income,test_expenses,test_tenant_isolation,test_transactions}.py`.

**Produces:**
- `EventBus` (subscribe/publish, exceptions logged not raised); events `income.created/paid`, `expense.created/paid`, `transaction.created`, `journal_entry.created`.
- `FinancialTransaction(financial_account_id, transaction_type ∈ INCOME|EXPENSE|TRANSFER|RECEIVABLE_COLLECTION|PAYABLE_PAYMENT|ADJUSTMENT, amount Numeric>0, currency, date, description, reference, status='ACTIVE', source_type, source_id, created_by)`.
- `record_transaction(db, org_id, account_id, type, amount, date, ...) -> FinancialTransaction` — locks the FinancialAccount row (`with_for_update()` on PG; plain get on SQLite), re-checks active, applies signed delta to `current_balance`, creates the row, publishes `transaction.created`. Single choke point; TRANSFER creates two rows sharing a `transfer_group_id`... **MVP: TRANSFER endpoint takes from/to and calls record_transaction twice + JE (Debit 1100/Credit 1100 same code — line-level accounts both 1100, acceptable) — keep simple.**
- `Income(date, customer_id?, description, amount, category_id, financial_account_id?, status ∈ PENDING|PAID|CANCELLED, notes, paid_at, cancelled_*)`; `Expense` mirror with `vendor_id`, `payment_method`, `reference`.
- Income service: `create_income(...)` (if status PAID → `pay_income` inline), `pay_income(...)` → record_transaction(INCOME) + `rules.income_paid(...)` JE (Debit 1100 / Credit category.account_code) + events; `cancel_income` only when PENDING (paid cancellation deferred to reversal milestone → 400 with Spanish message). Expense mirror (Debit category code / Credit 1100).
- `Customer`/`Vendor` CRUD (`/api/customers`, `/api/vendors`) with soft delete, search `q`, pagination envelope.
- `GET /api/transactions` (filters: account, type, date range) + `GET /api/income`, `POST /api/income`, `POST /api/income/{id}/pay`, `POST /api/income/{id}/cancel`, same for `/api/expenses`.

- [ ] Tests (the §47 criticals): income paid → account balance ↑, balanced JE, revenue credit; expense paid → balance ↓, expense debit; pending income moves nothing until paid; tenant isolation — Org B token cannot read/pay Org A income (404), list endpoints scoped; pagination shape `{items,total,limit,offset}`.
